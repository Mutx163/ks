# Bug 审查报告

- **项目：** 城科卷王
- **日期：** 2026-06-14
- **审查范围：** 数据新鲜度、数据正确性、加载速度
- **审查结论：** 发现 6 个确认 Bug（2 高 / 3 中 / 1 低）

## Bug 1（🔴 高）：「今日刷题」统计使用 UTC 时区，中国用户每天错 8 小时

**类别：** 数据正确性

**位置：** `worker/src/index.js` 第 783 行

```javascript
const today = new Date().toISOString().slice(0, 10) + '%';
```

`toISOString()` 返回 **UTC 时间**。中国用户在北京时间 00:00–07:59 期间，UTC 仍是前一天。例如：

- 北京时间 2024-01-16 02:00 → UTC 是 2024-01-15 18:00
- `today` = `'2024-01-15%'`，但用户期望看到 01-16 的数据

**同一问题还出现在：** `handleAdminOverview`（第 1053 行），管理员后台的「今日注册」「今日活跃」也是 UTC 日期。

**影响：** 首页「今日刷题」数字在北京时间每天凌晨 0:00–07:59 显示的是**前一天**的数据。同一个 Bug 出现在 2 处。

**修复建议：** 使用中国时区（UTC+8）计算"今天"：

```javascript
// 替换 new Date().toISOString().slice(0, 10)
const now = new Date();
const chinaOffset = 8 * 60; // UTC+8，单位分钟
const local = new Date(now.getTime() + chinaOffset * 60 * 1000);
const today = local.toISOString().slice(0, 10) + '%';
```

## Bug 2（🔴 高）：前端 `cache: 'no-store'` + `_ts` 时间戳完全废掉了 Worker 的 CF 边缘缓存

**类别：** 性能

**前端位置：** `js/api.js` 第 87、92 行

```javascript
urlObj.searchParams.set('_ts', Date.now().toString());  // 每次URL不同
const res = await fetch(url, { cache: 'no-store', ... });  // 请求头带 Cache-Control: no-store
```

**后端位置：** `worker/src/index.js` 第 1292 行

```javascript
// 缓存 5 分钟（减少重复请求，更新延迟最多 5 分钟）
return json({...}, 200, origin, 300);  // 设置 Cache-Control: public, max-age=300
```

**矛盾分析：**

1. Worker 故意设置了 5 分钟边缘缓存（注释明确说明意图）
2. 前端 `_ts=Date.now()` 使每次请求 URL 唯一 → CF 边缘视为不同资源
3. 前端 `cache: 'no-store'` 请求头告诉所有缓存层（包括 CF 边缘）不要存储响应

**结果：** Worker 的 `max-age=300` 是**死代码**，每个请求都穿透到 Worker 源站。HTML 中的注释已佐证开发者发现了这个副作用：

```html
<!-- 预加载已移除：因为实际请求带 _ts 参数，预加载的请求未被使用 -->
```

**影响：** 中国用户每次打开页面，所有题库数据都打到 Worker 源站（非中国区域），无法利用 CF 边缘节点缓存。假设 5 个题库 = 6 次 API 调用全穿透。

**修复建议：** 改用 ETag/If-None-Match 条件请求，兼顾新鲜度和性能：

```javascript
// api.js — 移除 _ts 和 cache: 'no-store'，改用默认 HTTP 缓存行为
const res = await fetch(url); // 浏览器自动处理 ETag 条件请求

// worker/src/index.js — 为题库数据添加 ETag
const etag = `"${bank.version || Date.now()}"`;
if (request.headers.get('If-None-Match') === etag) {
    return new Response(null, { status: 304, headers: { ETag: etag } });
}
// 正常返回时带上 ETag 和短缓存
headers['ETag'] = etag;
headers['Cache-Control'] = 'public, max-age=60';
```

这样首次请求返回完整数据 + ETag，后续请求发送 If-None-Match → 数据未变返回 304（极快，无 body），数据变了返回新数据（新鲜）。

## Bug 3（🟡 中）：题库加载 N+1 查询模式 + 部分失败静默丢弃

**类别：** 性能 / 用户体验

**位置：** `js/bankLoader.js` 第 57–72 行

```javascript
async loadAllBanks() {
    const list = await this.loadBankList();           // 第 1 次：获取题库列表
    const results = await Promise.all(
        list.map((b) => this.loadBank(b.id))          // 第 2~N+1 次：逐个加载题库
    );
    const banks = results.filter(Boolean);
    return banks;
}
```

每个 `loadBank` 调用 `requestWithRetry`（最多 3 次尝试，指数退避 1s/2s）。

**附加问题：** 失败的题库被 `filter(Boolean)` **静默丢弃**。`app.js` 只检查全部失败的情况（`banks.length === 0`），部分失败无任何提示。用户可能知道有 5 个题库但只看到 3 个，不知道原因。

**影响：** 5 个题库 = 6 次并行 API 调用，最慢的一次决定总耗时。加上 Bug 2（无边缘缓存），每次都要穿透到源站。

**修复建议：**

1. **短期：** 增加 Worker 端批量接口 `/api/banks/all` 一次返回所有题库数据（含题目），减少到 1 次 API 调用
2. **短期：** 部分失败时在页面顶部显示提示（如「2 个题库加载失败，点击重试」）
3. **中期：** 改为增量更新 — 首次全量拉取后，后续只请求 `?since=version` 检查是否有更新

## Bug 4（🟡 中）：`pushProgress` 的 Promise 错误被静默吞掉

**类别：** 数据可靠性

**位置：** `js/api.js` 第 250–261 行

```javascript
pushProgress(progress) {
    if (!this.isRegistered() || !progress) return;
    clearTimeout(this._syncTimer);
    this._syncTimer = setTimeout(() => {
        this.request('/api/progress', {
            method: 'POST',
            body: JSON.stringify({ deviceId: this.getDeviceId(), progress })
        })
        // ← 没有 .then() 也没有 .catch()
    }, 5000);
},
```

对比同文件的 `pushStats`（第 280 行）正确处理了 `.then()` 和 `.catch()`。

**影响：** 云端进度同步（间隔重复数据 `nextReviewAt`、`easeFactor` 等）请求失败时，用户完全不知情。换了设备可能发现复习进度丢失。

**修复建议：**

```javascript
this.request('/api/progress', {
    method: 'POST',
    body: JSON.stringify({ deviceId: this.getDeviceId(), progress })
}).catch(err => {
    console.warn('[API] pushProgress 失败:', err.message);
    // 可选：标记待重试，下次 autoSync 时补推
});
```

## Bug 5（🟡 中）：KaTeX CSS 阻塞渲染 + 外部 CDN 无降级方案

**类别：** 性能 / 中国可用性

**位置：** `index.html` / `quiz.html`

```html
<!-- KaTeX CSS — jsdelivr（阻塞渲染！） -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16.9/dist/katex.min.css" />

<!-- Prism.js — bootcdn -->
<link rel="stylesheet" href="https://cdn.bootcdn.net/ajax/libs/prism/1.29.0/themes/prism-tomorrow.min.css" />

<!-- Lucide 图标 — jsdelivr -->
<script src="https://cdn.jsdelivr.net/npm/lucide@0.344.0/dist/umd/lucide.min.js" defer></script>
```

**问题：**

- `<link rel="stylesheet">` **会阻塞首屏渲染**，浏览器必须等 CSS 下载完才绘制页面
- `cdn.jsdelivr.net` 在中国部分地区连接不稳定
- 无任何 `onerror` 回退或本地备份

**影响：** CDN 慢时白屏时间增加；CDN 不可用时功能降级（无图标/无数学公式/无代码高亮）。

**修复建议：**

1. **短期：** 将 KaTeX CSS 改为 `<link rel="preload" as="style" onload="this.rel='stylesheet'">` 不阻塞渲染
2. **中期：** 将关键 CDN 资源打包进 Vite 构建（`npm install katex prismjs lucide`），消除外部依赖
3. **中期：** 如保留 CDN，增加 `onerror` 回退加载本地备份

## Bug 6（🟢 低）：首页云同步完成后不重新渲染统计数据

**类别：** 数据新鲜度

**位置：** `js/app.js`

```javascript
this.render();  // ← 先用本地数据渲染统计面板

API.autoSync()
    .then(() => {
        this.state.stats = Storage.getGlobalStats();  // ← 更新了数据引用
        // ← 但没有重新调用 renderStatsOverview()
    });
```

**影响：** 如果用户在另一台设备刷了题，当前设备首页显示的是同步前的旧统计，直到手动刷新页面。

**修复建议：**

```javascript
API.autoSync()
    .then(() => {
        this.state.stats = Storage.getGlobalStats();
        // 同步完成后重渲染统计面板
        this.renderStatsOverview();
    });
```
