## 六、待后端官交付后要补跑 / 注意

- **B3 依赖 AI 开关**：本地 `app_config.enabled=false` 时一律 403「未启用」，测不出配额。后端官需在本地开一个测试 AI 配置（或 mock），或接受 B3/B3b 记 SKIP 并在发布说明里写明「配额未本地实测」。
- **B1 的顺序语义**：脚本先做一次正确绑定（R2-0），再连打错误码，最后再验正确码。若后端采用「整 IP 冷却」，最后那次正确码会 429 → B1 判 FAIL；请后端官确认预期是「失败计数按 IP+deviceId、正确码可放行」还是「整 IP 冷却」。
- **B2 冷却会锁管理员**：当前设计下正确密码也可能被冷却拒绝。脚本会记录 `correctAfter`，若后端口径允许「正确密码穿透冷却」，请明确写进契约。
- **限流是内存态**：单 isolate 近似，验收只证明本地行为，不得对外宣称「彻底加固」。
- 生产验收：B1/B2 的 429 可在发布后用少量错误请求验证（会消耗一次失败计数），**B3 生产验证需要 AI 已启用**；R4 生产只需 `GET /api/bank/fixture-design-ch2` = 87 + 12 图 200（只读）。

### 8.5 本地 IP 模拟与线上语义差异（必须写进结论）

- 本地 miniflare 请求**没有** `CF-Connecting-IP`；`getClientIp()` 回退到 `X-Forwarded-For`，测试脚本因此注入 `203.0.113.x` 模拟客户端 IP。
- 线上 Cloudflare 由边缘**强制注入** `CF-Connecting-IP`，客户端无法伪造 `X-Forwarded-For` 覆盖它（且 `getClientIp` 优先读 CF 头）。
- 所以：**本地 429 证明的是「限流逻辑/阈值/顺序正确」，不能证明线上阈值表现一致**（例如 NAT 后真实用户共享同一出口 IP 的聚合效应、IPv6 地址分布、多 isolate 内存计数不共享，本地都测不出）。
- 同理，本地浏览器页面请求不带任何 IP 头，B-2/B-3 的 IP 维度在页面上是空键——这两个限流项**只能用带 `X-Forwarded-For` 的 HTTP 脚本验**，UI 端只能验 B-1（deviceId 维度）与 429 文案。
