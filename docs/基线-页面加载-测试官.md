## 四、首屏阻塞项判断

1. **渲染阻塞 CSS**：`index.html` 4 个 `<link rel=stylesheet>`、`quiz.html` **5 个**（含 KaTeX CSS 28 KB）、`admin.html` 2 个（admin.css 41 KB + base）。这些都在 `<head>`，直接参与 FCP。
2. **KaTeX 全量进刷题页**：`vendor-katex` **258 KB JS + 28 KB CSS + 多个 woff2**，即使题库没有公式也会下载；这是刷题页最大单笔开销，也是 LCP 4412 的主要推手之一（还叠加题库 API 往返 + 渲染）。
3. **51.la 第三方 SDK**：首页 `index.html:399-407` 动态插入，注释称「首屏完成后空闲加载」，但实测仍产生 **110 KB / 4 页**（home、SPA 路由三页都走这个壳）；Fast 4G 下占用明显，且不在我们控制内。
4. **模块脚本瀑布**：入口 `index-*.js` → `debug-*.js`（应用主逻辑 55 KB）→ 各 chunk；module 本身不阻塞解析，但**下载 + 执行**在 4× CPU 下降速明显（DCL 1955ms）。
5. **刷题页 LCP 依赖异步数据**：FCP 2364 / LCP 4412，差 2 秒；题目区要等银行 API 返回后再渲染，骨架屏未参与 LCP。
6. **后台页 FCP 2136 最慢**：admin 单包 148 KB + admin.css 41 KB，9 个请求就 313 KB，首屏解析/执行成本高。

## 五、复现方式

```powershell
$env:VITE_OUT_DIR='.tmp-perf/dist'; $env:VITE_API_BASE='http://127.0.0.1:8787'
npm run build
pwsh -File scripts/dev-services.ps1 -Action start -Owner 测试官 -Task perf -Service api
node .tmp-perf/serve.mjs          # 3000 静态服务（dist）
$env:PERF_PAGES='/'; $env:PERF_OUT='baseline-auth'
node .tmp-perf/baseline-auth.mjs
# 刷题页单独跑（必须带 bank 参数）
$env:PERF_PAGES='/quiz.html?bank=smoke-c&mode=all'; $env:PERF_OUT='baseline-quiz'
node .tmp-perf/baseline-auth.mjs
pwsh -File scripts/dev-services.ps1 -Action stop
```
