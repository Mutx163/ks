## 4. 100GB 流量够不够（按真实页面体积算）

### 4.1 计算口径

- 页面体积（ks 提供）：首页 ~320KB、刷题页 ~268KB、后台 ~176KB（冷加载，含 JS/CSS；线上六页合计约 447KB）
- 缓存：静态资源带指纹，二次访问基本命中浏览器缓存，只需 HTML（~20–30KB）
- 题库图片：`public/images/` 12 张共 2.4MB，单张约 0.11–0.56MB；假设每 3 次访问看 1 张图（平均 0.2MB/次）
- 每次访问估算：
  - **冷访问**（首次/清缓存）：300KB 页面 + 1/3 张图 ≈ **0.37MB**
  - **热访问**（缓存命中）：30KB + 1/3 张图 ≈ **0.10MB**
  - **典型加权**（30% 冷 / 70% 热）≈ **0.18MB/次**
  - **极端保守**（每次全冷、每次 1 张图）≈ **0.5MB/次**
- 可用流量：100GB − 探针 3.6GB − 系统更新/SSH 约 2GB ≈ **94.4GB/月**
- **不计** API 流量：题库/同步/排行榜仍走 Cloudflare，不消耗华为流量（这也是「半程加速」的原因）

### 4.2 三档估算

| 使用强度 | 每用户月流量（典型 0.18MB/次） | 100GB 可支撑用户数（典型） | 极端保守（0.5MB/次）月流量 | 可支撑用户数（保守） |
| --- | ---: | ---: | ---: | ---: |
| 轻度：3 次/天 | ~16 MB | **≈5,900 人** | ~45 MB | **≈2,100 人** |
| 常态：10 次/天 | ~54 MB | **≈1,750 人** | ~150 MB | **≈630 人** |
| 重度：30 次/天 | ~162 MB | **≈580 人** | ~450 MB | **≈210 人** |

补充：
- 若用户大量看图片题（每天 10 张图 = 2MB/天 = 60MB/月），重度档会再少约 1/4 容量。
- 100GB/月 ≈ 平均 **0.31 Mbps** 出流量；峰值还受实际带宽规格限制（1Mbps 下 300KB 页面约 2.4s，5Mbps 约 0.5s），**需要控制台确认带宽**。
- 超限后果（限速/额外计费/null route）需在华为云确认；建议自建流量监控并在 80GB 告警。

## 5. 混合架构：搬静态 ≠ 全站变快

现状：前端调 `https://ks-api.mutx.ccwu.cc/api/*`（Cloudflare Worker + D1）。

- **能省的**：HTML/CSS/JS/字体/图片的出境流量，改由贵阳节点直出，国内 TTFB 有望从当前 1.4–1.7s 降到 0.1–0.3s 量级（参考国内云文档站实测）。
- **省不掉的**：题库、同步、排行榜、登录仍回 Cloudflare，实测 API TTFB **1.4–4.5s**。刷题页真正「等」的是这个接口，不是静态资源。
- **CORS**：如果继续用 `ks.mutx.ccwu.cc` 这个域名（只换解析），Worker 白名单已包含它，**不用改 CORS**；若换新域名，必须改 `ALLOWED_ORIGINS` 并部署 Worker。
- **HTTPS**：需要 Nginx/Caddy + 证书（Let's Encrypt 免费，需 80 端口验证或 DNS-01）；安全组要放行 80/443。
- **法规**：域名备案是前提，否则不能合规上线。

## 6. 明确建议

**结论：有条件搬，但优先级低于「API 优化」和「备案 + EdgeOne 大陆区」。**

- **满足以下全部条件才建议搬**：
  1. `ccwu.cc` 已有 ICP 备案，且能在华为云侧接入；
  2. 控制台确认带宽 ≥3–5Mbps、超流量策略可接受；
  3. 接受「静态在贵阳、API 在 CF」的半程加速；
  4. 愿意维护 Nginx/证书/监控（一次性约 1–2 小时，加每月证书续期自动化）。
- **不满足任一条则不搬**：没有备案时上线不合规；带宽/流量不明时可能搬完更慢或很快超限。
- **如果目标是「国内明显更快」**：优先级应是 ① 给 EdgeOne 切大陆/含大陆区域（需备案，同平台成本最低）→ ② 优化 API（缓存/减少请求/就近）→ ③ 才考虑搬静态到华为 ECS。
- **现成收益**：这台机器 2C/1.7G/40G 跑静态站绰绰有余，现有探针只占 3.6GB/月；如果只是「想把静态放国内试试」，成本很低，但请先确认备案与带宽。
