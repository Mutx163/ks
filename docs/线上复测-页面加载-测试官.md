### 2.1 改前对照的一个坑（必须记）

别名域名不在 Worker 的 `ALLOWED_ORIGINS` 白名单（`worker/src/index.js:17-23` 只含 `ks.mutx.ccwu.cc`、`ks-cjx.pages.dev`、localhost/127.0.0.1:3000），所以直接拿别名跑，页面 API 全被 CORS 拦（控制台 `GET /api/banks 异常: Failed to fetch`），渲染成「暂无可用题库」空状态，字节也只有 20 万而不是带数据的 35 万。

修正办法：起一个本地代理 `8788`，转发到 `8787` 并把 `Access-Control-Allow-Origin` 改成 `*`（代理还去掉了 `content-encoding`，否则 Node 已解压的 body 会被浏览器按 br 二次解压失败）。改前臂的 API 走代理，改后臂直连 worker。修正后改前首页字节从 203 KB 回到 **352 KB**（带数据），对照才成立。

## 4. 为什么线上 FCP 不能当判据

三轮同条件 A/B 的结论方向互相矛盾：

| 页面 | 第 1 轮（3 对） | 第 2 轮（3 对，代理修正） | 第 3 轮（5 对，交替顺序） |
|---|---|---|---|
| `/` | −26.1% | −4.5% | −12.0% |
| `quiz` | −18.4% | −2.8% | −14.4% |
| `admin` | −20.0% | +0.9% | +25.2% |
| `leaderboard` | +14.6% | +24.7% | −0.2% |
| `analysis` | +22.1% | +56.8% | +6.3% |
| `trend` | −14.9% | +53.0% | +30.3% |

**噪声底实验**（同一版本对自己测，A/B 都是当前线上，6 对）：`analysis` **+15.9%**、`trend` **−19.6%**、`leaderboard` −3.5%，TTFB 抖动 300→900 ms。也就是说 ±20% 的 FCP 差异在这个环境里**连方向都不可信**。

按页面合看，只有两类结论站得住：

- **首页与刷题页方向一致为负**（首页 −26.1% / −4.5% / −12.0%，刷题 −18.4% / −2.8% / −14.4%）：三轮没有一次反转，幅度随边缘抖动变化。刷题页的页面自身成本 −30.4% 与 55.9% 字节削减对得上。
- **admin 与三页壳方向不稳**：admin 的改前 FCP 取决于 `cdn.jsdelivr.net` 当时快慢（4.7 s 或 2.2 s 两条时间线都测到），中位数自然随机；三页壳字节只 +1.5~1.8%、请求数不变，差异小于同版本自测噪声。


噪声来源可指认：CF 边缘 TTFB 300–1050 ms 抖动、第三方 `cdn.jsdelivr.net` 字体链 0–4.7 s 不定、`static.cloudflareinsights.com/beacon.min.js` 不返回长度、CPU 4× 下的主线程争用。

### 4.1 能复现的那部分：admin 阻塞链确实被移除

同一页各跑 2 次，记录资源时间线（Fast 4G + CPU 4×）：

后台登录「密码框可见」相对 HTML 到达时间：改后 **855 / 1045 ms**，改前 **1433 / 2319 ms**。

## 7. 顺带发现（既有行为，不是本批引入）

1. **Pages clean URL 让三页 SPA 重定向失效**：`js/utils.js:853-859` 只在 `pathname` 以 `.html` 结尾时把 `leaderboard/analysis/trend` 跳去 `index.html#/…`；而 Pages 会把 `/leaderboard.html` 308 成 `/leaderboard`，于是线上打开的是**独立页**（11–13 请求、53–57 KB），而不是 SPA 路由（本地基线里的 51–59 请求、660 KB）。线上与本地行为不一致，一直如此，本批没动。
2. **部署别名不在 CORS 白名单**：预发/回滚验证若直接用 `<deploy-id>.ks-cjx.pages.dev`，API 会被拦成空状态，容易误判成「回滚后功能坏了」。要么把别名域名加进 `ALLOWED_ORIGINS`（需 ks 拍板，属安全策略），要么用本文件的代理办法。
3. **`debug.css`（8.3 KB）仍在各页阻塞路径**：它其实是 `base.css` 被 Rollup 收进共享 chunk 后沿用命名，不是调试样式，属命名误导，性能上无害。
