## 健康检查语义确认

- 判定依据是 **HTTP**：api 打 `/api/banks`（200 且 `ok:true`）、web 打 `/`（200 且含标题），不是只看 pid 存活。
- `pid=` 是脚本记录的进程（npx 包装层），`port=... LISTEN pid=` 是实际监听进程（workerd/vite），两者不同属正常；脚本用命令行指纹校验归属。

## 操作注意（给后来人）

1. **不要把 `start` 的 stdout 直接接管道**（如 `| Out-String`）：服务进程会继承句柄，外层 pwsh 会一直不返回（本次实测挂起 >4 分钟，服务其实已起好）。用文件重定向：`cmd /c "pwsh -File scripts/dev-services.ps1 -Action start > log.txt 2>&1"`。
2. `status` 是只读、不抢互斥锁，可在别人 start 中随时查看（本次已验证）。
3. 收工顺序：`stop` → `status` → 进程计数 → 端口监听数 → 内存，五项一起贴。
