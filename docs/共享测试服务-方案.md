# 共享测试服务 · 适配方案（参照 mikcb）

- 日期：2026-11-14
- 作者：情报官（只读调研 + 文档，不实现脚本、不起服务）
- 调研对象：`C:\cursor\mikcb` 的 `AGENTS.md`、`CLAUDE.md`、`.agents/reference/local-toolchain.md`、`.agents/reference/testing-policy.md`、`scripts/safe-gradle.ps1`
- 背景：本机 32GB 内存，2026-11-14 清出 115 个残留 `wrangler/workerd/esbuild` 进程，可用内存一度只剩 1.91GB。根因不是某个 Bot 犯错，而是**没有统一入口、没有单实例锁、收工没有核对**。
- 目标：把 `wrangler dev`（Worker API + 本地 D1）与 `vite`（页面）做成两个**受管的共享服务**，同一时刻最多一个实例，测试脚本可复用，收工必须 stop 并贴 status。

## 1. mikcb 的五问五答

### 1.1 哪些东西被做成共享服务

| 共享对象 | 形态 | 谁起停 |
| --- | --- | --- |
| Gradle 构建（L1/L2） | 全机唯一构建闸门 | Agent 通过 `scripts/safe-gradle.ps1` 起，闸门自己排队；L3/L4 出包与真机由**用户**跑 |
| Gradle daemon | 单 daemon 复用 | 由 Gradle 自己管，`org.gradle.daemon.idletimeout=600000` 写在 `android/gradle.properties`，**禁止命令行 `-D`**（会造出互不复用的第二个 daemon） |
| 实体设备（Android） | 共享设备，只读接入 | 只有用户当场明确允许才操作；输入注入、改设置一律禁止 |
| Git 工作区 / 暂存区 | 多 Agent 共享工作区 | 靠路径限定提交与认领文件避让，不靠分支隔离 |
| CPU 核 | `scripts/cpu-governor.ps1` 分配亲和性 | 用户/维护者起 watchdog；watchdog 必须恰好 1 个 |
| 共享件写权 | `claims/<批次>.md` 认领文件 | 有文件 = 有人在做；后到者避让 |

> 注意：mikcb 是 Android/Compose 项目，**没有**浏览器 dev server（`site/` 的 Next.js）的统一共享管理；它的“共享服务”主要指 **Gradle 构建闸门**。端口、健康检查这部分我们只能借它的闸门思路，不能照抄现成实现。

### 1.2 谁调用、怎么调用

| 级别 | 调用方式 | 说明 |
| --- | --- | --- |
| L0 模块单测（Agent，最高频） | `pwsh -File scripts/test-kotlin-module.ps1 -Module "pages/<域>"` | 本地内置 kotlinc + JUnitCore，只编当前模块，避免被别人的半成品干扰 |
| L1 编译验证（Agent，每批一次） | `pwsh -File scripts/safe-gradle.ps1 :app:compileDevDebugKotlin` | **必须过闸门**，裸跑 `gradlew` 算违规 |
| L2 单测（Agent，每批一次） | `pwsh -File scripts/safe-gradle.ps1 :app:testDevDebugUnitTest` | 带排队锁 |
| L3 / L3.5 / L4 | 用户在 AS / 命令行跑 | Agent 只声明“编译通过 / JVM 单测通过”，不得声明“能跑” |

- 端口约定：mikcb 的构建闸门不涉及端口；唯一的健康检查样例是手机端 LAN 编辑服务 `GET http://<ip>:<port>/api/v1/health` → `{"ok":true,...}`（`docs/BUILD_TROUBLESHOOTING.md`），端口随机 `49152–65535`。
- 结论：**端口 + 健康检查要由 ks 自己定**，见第 2 节。

### 1.3 单实例怎么保证

1. **Windows 内核级命名互斥锁**：`scripts/safe-gradle.ps1` 用 `Global\Mikcb_Gradle_Build_Mutex`（拿不到 Global 时退回 `Local\`），`WaitOne(timeoutMs)` 排队；捕获 `AbandonedMutexException`（持锁进程崩溃）后继续；结束 `ReleaseMutex` + `Dispose`。
2. **锁后二次核对**：拿到锁还要等外部 `GradleWrapperMain` 进程清零才开跑（最多等 30 分钟，超时退出码 112），防止绕过闸门的裸构建。
3. **共享件用认领文件**：`claims/<批次>.md` 创建成功才算领到，不是靠口头约定。
4. **副作用配置单点**：daemon 的空闲超时只写在 `gradle.properties`，命令行不加 `-D`，避免第二个 daemon。

### 1.4 生命周期规则

- 什么时候起：L1/L2 只在**每批交付时一次**；L0 可以高频但也不是免费（实测单次真 JVM 616–829MB）。
- 什么时候不许起：**半成品代码不跑全局编译**；用户在 AS 里构建时**不要并发跑**。
- 测试：只跑单文件并带 `--timeout`，全量验证留给集成者**串行**做。
- 收工核对：确认没有遗留未提交修改，并**清掉测试残留进程**；测试策略文档给了保守清理脚本，只清“父进程已退出”的 `flutter_tester.exe`，正在跑的一律不碰。
- 汇报口径：说清“清了几个、回收多少内存”；不确定就先只读扫描、把结果报给用户再清。

### 1.5 违规代价写在哪、谁检查

- **常驻规则**：`AGENTS.md` 开头的铁律，且规定**行数硬上限 200 行**，新增一条必须同次删一条等量旧规则——规则本身不许膨胀。
- **落地文档**：`.agents/reference/*.md` 只放“为什么、实测数字、长步骤”，避免常驻文件变长。
- **执行者**：闸门脚本本身就是检查器；裸跑 `gradlew` 直接绕开锁，属于明写违规。
- **守卫**：`local/verify_phase3_ledger.ps1` 检查进度账与 AGENTS 一致；pre-commit 钩子；`npm run verify-notes`；`ComposePageStyleGuardTest` 等源码守卫。
- **事故留痕**：文档里记录实测代价——2026-10-27 单日 **577 个** Gradle 一次性 JVM、489 分钟构建、**71% 失败**；一次攒了 **16 个**孤儿 `flutter_tester`、约 1.6GB；本机 2026-11-14 清出 **115 个** wrangler 残留。

## 2. 适配到 ks 的方案

### 2.1 服务清单与固定端口

| 服务 | 命令 | 固定端口 | 说明 |
| --- | --- | --- | --- |
| `api` | `npx wrangler dev --local --port 8787 --persist-to .tmp-services/d1` | **8787** | Worker API + 本地 D1；`NODE_OPTIONS=--dns-result-order=ipv6first` 只在需要连 Cloudflare 时加，本地 dev 不需要 |
| `web` | `npx vite --port 3000 --strictPort` | **3000** | 页面；`--strictPort` 保证端口被占时直接失败，不静默换端口 |

- 固定端口是给**测试脚本、文档、回滚命令**一个稳定坐标；临时端口（8791/8795/8822…）正是这轮 115 个残留的来源之一。
- 端口被占时**不自动换端口**：换端口会让测试脚本连到错的实例，宁可报错。
- `web` 启动时由脚本生成 `.tmp-services/vite.dev.config.mjs` 包装器，把 `**/.tmp-*/**`、`**/.git/**`、`**/node_modules/**` 排除出 watch：仓库里遗留的 Chrome profile / sqlite 被锁时会触发 `EBUSY` 直接拖崩 vite（实测 `.tmp-r2-bank/chrome-evidence` 已复现）。包装器只覆盖 dev server 监听项，其余沿用项目 `vite.config.js`，不改业务配置。

### 2.2 目录布局

```text
.tmp-services/
├── api.pid          # {"pid":1234,"port":8787,"startedAt":"...","cmdline":"..."}
├── api.log          # 启动时截断，只留本次
├── web.pid
├── web.log
├── lease.json       # {"owner":"发布官","task":"R4 复验","startedAt":"...","expiresAt":"..."}
└── d1/              # wrangler --persist-to，本地 sqlite
```

- `.gitignore` 现有 `.tmp-*/` 已覆盖，仍建议**显式加一行** `.tmp-services/`，让规则一眼可见。
- 日志落盘便于失败时贴尾部，不用回头翻终端。

### 2.3 统一入口：`scripts/dev-services.ps1`

```powershell
pwsh -File scripts/dev-services.ps1 -Action start   [-Service api|web|all] [-Owner "发布官"] [-Task "R4 复验"]
pwsh -File scripts/dev-services.ps1 -Action stop    [-Service api|web|all]
pwsh -File scripts/dev-services.ps1 -Action status
pwsh -File scripts/dev-services.ps1 -Action restart [-Service api|web|all]
```

- **start**：拿 `Global\Ks_DevServices_Mutex` → 检查 lease → 对每个服务先探端口与健康检查：已健康则**复用并打印 PID**；未启动则启动、写 PID、30 秒内轮询健康检查；失败则输出日志尾部并非零退出。
- **stop**：读 PID → 校验命令行确实匹配本项目服务 → `taskkill /PID <pid> /T /F` 杀进程树（wrangler 会拉 workerd 子进程，必须 `/T`）→ 删 PID → 释放 lease。
- **status**：打印 lease（谁在用、什么任务、何时到期）+ 每个服务的 PID/端口/健康状态/命令行前 120 字；全在退出码 0，有缺失退出码 1。
- **restart** = stop + start，仅用于“配置改了要重载”，不允许拿它当日常开关。

> 命名互斥锁只包住 start/stop 的临界区，**不长期持有**；真正防重复实例的是“端口 + PID + 健康检查”三件套，锁是防两个 Bot 同时执行 start 的竞态。

### 2.4 单实例与端口冲突行为

四重判定，任何一重不通过都不启动：

1. **命名互斥锁** `Global\Ks_DevServices_Mutex`（拿不到 Global 退回 `Local\`），捕获 `AbandonedMutexException`。
2. **lease 文件**：`lease.json` 存在且 `expiresAt` 未过 → 拒绝启动，提示“当前由 X 在跑 Y，先 stop 或等到期”。
3. **端口探测**：8787/3000 已监听时，先做健康检查——
   - 健康且 PID 文件匹配 → **复用**，不重复起；
   - 健康但无 PID 文件（历史残留）→ 提示并允许 `-Adopt` 接管（默认拒绝）；
   - 监听但不健康/不是本项目进程 → **拒绝启动**，输出占用 PID 与命令行，交 ks 决定，**不自动 kill**。
4. **PID 指纹**：PID 文件里的进程必须存在，且命令行同时含 `wrangler`/`vite`、`--port 8787`/`3000`、工作目录在 `C:\cursor\ks`；任一不符视为失效 PID，清理后重新判断。

崩溃恢复：PID 文件存在但进程不在 → 自动清理并提示“上次未正常 stop”；锁被遗弃 → 捕获异常后继续。

### 2.5 健康检查

| 服务 | 探针 | 通过条件 | 超时 |
| --- | --- | --- | --- |
| api | `GET http://127.0.0.1:8787/api/banks` | HTTP 200 且 JSON `ok:true` | 单次 2s，启动轮询 30s |
| web | `GET http://127.0.0.1:3000/` | HTTP 200 且 HTML 含 `<title>城科卷王</title>` | 单次 2s，启动轮询 30s |

- **以 HTTP 为准，不以“进程还在”为准**：进程活但端口没起来 = 不可用。
- 健康检查失败时输出 `.tmp-services/*.log` 最后 30 行，不再让测试脚本“卡 300 秒”。

### 2.6 测试脚本怎么改成“先探测、活着就复用”

在每个测试脚本入口加一段（伪代码，落地时抽成 `scripts/lib/ensure-service.ps1`）：

```powershell
function Ensure-Service([string]$Name) {
    $base = if ($Name -eq 'api') { 'http://127.0.0.1:8787' } else { 'http://127.0.0.1:3000' }
    if (Test-Health $Name) { Write-Host "[reuse] $Name @ $base"; return $base }
    & pwsh -File scripts/dev-services.ps1 -Action start -Service $Name -Owner $env:KS_OWNER -Task $env:KS_TASK
    if (-not (Test-Health $Name)) { throw "$Name 启动失败，见 .tmp-services/$Name.log" }
    return $base
}
```

规则：

- 测试脚本**只 Ensure，不负责 stop**；stop 由本轮任务 owner 收工统一执行，避免两个脚本互相把对方的服务关掉。
- 如果任务确实需要独占（例如改 Worker 代码），用 `-Owner` + lease 标明，并在报告里写“本轮独占 api”。
- **禁止**测试脚本自己 `npx vite` / `npx wrangler dev` 绕开统一入口；出现即视为违反 AGENTS.md 并发纪律。

### 2.7 生命周期与收工核对

- 起服务前：先 `status` 确认没人占用；按纪律**先报 ks**，同一时刻只允许一个批次。
- 测试期间：单实例、固定端口；需要重启用 `restart`，不要手动杀进程再起。
- 收工三件事（缺一不可）：
  1. `-Action stop -Service all`；
  2. `-Action status` 贴输出，证明 `lease=无`、两个服务都不在；
  3. 贴进程核对 + 剩余内存：
     ```powershell
     Get-CimInstance Win32_Process |
       Where-Object { $_.Name -in @('node.exe','workerd.exe','esbuild.exe') -and $_.CommandLine -match 'wrangler|vite' }
     ```
- 残留处理：只清理“父进程已退出 + 命令行匹配本项目 + 不在 lease 里”的进程；其余先报 ks，不误杀。
- 看到别人的残留：一并上报，由 ks 指定执行人清（同本轮 115 个进程的处理方式）。

### 2.8 与 AGENTS.md / 构建的关系

- 本方案是 2026-11-14 新增「并发与资源纪律（强制）」的**可执行化**：纪律第 2 条（本地服务只留一个）、第 3 条（收工三件事）在这里有具体入口。
- **零新增依赖**：只用 pwsh 内置的 `[System.Threading.Mutex]`、`Invoke-WebRequest`、`Get-CimInstance`、`taskkill`。
- 不改 `vite.config.js` 端口；端口由命令行 `--port`/`--strictPort` 指定，CI/构建不受影响。
- 不改变生产发布：本方案只作用于本地 dev server。

## 5. 风险与边界

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 命名互斥锁只在本机 Windows 会话有效 | WSL/容器/其他机器不共享 | 跨环境靠端口+lease，不承诺跨机互斥 |
| `wrangler dev` 会拉 `workerd` 子进程 | 只杀父进程会留下 workerd | `taskkill /T` 杀树；status 里同时核对 workerd |
| 端口固定可能撞用户其他程序 | 3000/8787 可能被占 | 拒绝启动并输出占用 PID，交 ks 决定；不自动 kill |
| 健康检查只能证明“服务在” | 不能证明数据/题库正确 | 验收仍需测试脚本自己的断言 |
| lease 过期时间可能被误设 | 过长会挡住别人 | 默认 2 小时，`status` 显示剩余时间，可 `-ForceRelease`（需 ks 同意） |
| 本方案不解决“谁先动手” | 两个 Bot 同时想跑仍会抢锁 | 纪律仍是“先报 ks、串行派单”，锁只是最后一道保险 |

## 6. 验收标准（实现后）

1. 连续两次 `start -Service all`：第二次输出 `reuse`，进程数不增加。
2. 端口被其他程序占用时 `start`：非零退出，输出占用 PID/命令行，不自动杀。
3. 手动删掉 PID 文件但进程还在：`status` 能识别（端口+健康检查）并提示 `-Adopt`。
4. `stop` 后 `status`：退出码 1，无 lease，8787/3000 无监听。
5. 测试脚本在服务已起时输出 `[reuse]`，在服务未起时能自己起并等到健康。
6. 收工报告模板：`stop` 输出 + `status` 输出 + 进程核对 + 剩余内存。
