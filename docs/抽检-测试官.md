## 三、偏差明细（4 条，均不影响结论）

### D1 后端 admin handler 计数（合并稿 3.1 第 154 行）
- 报告：「35 个 `handleAdmin*` 中 34 个自校验」
- 实测：**36 个 `handleAdmin*`，35 个自校验**（逐个函数体检测 `requireAdmin(`，唯一例外 `handleAdminUserDetail`@1179）
- 来源：后端官 `docs/ks-audit-backend.md` 第八节「验证 4」同款计数；合并稿 1.2 又写「管理员路由 36」，与 154 行自相矛盾
- 影响：结论不变（唯一鉴权例外仍是 `handleAdminUserDetail`），只需把数字改为 36/35

### D2 题库解析缺失的字段形态（合并稿 4.3 第 242 行、4.6 Q-2 第 265 行）
- 报告：`explanation` 缺 10，「值为 **null**」/ `explanation:null`
- 实测：这 10 道题（`gemini-code-1780672768438` id 144–153）**根本没有 `explanation` 键**，解析结果为 `undefined`；文件里既不是 `null` 也不是空串
- 影响：数量与 id 全对，结论不变；但下游若按 `=== null` 写校验会漏检，建议改为「缺 `explanation` 字段」

### D3 `dist/` 体积口径（合并稿 1.4 第 72 行）
- 报告：「99 文件 4.4 MB」
- 实测：99 文件、**4,551,165 字节**（≈4.34 MiB / 4.55 MB）
- 影响：文件数一致，体积按 MiB 四舍五入应为 4.3；仅口径问题

### D4 我自己的迁移归因（已回改 `docs/体检-测试官.md`）
- 我第 1 阶段写「`schema.sql` 没有 ALTER TABLE 迁移」，后端官指出仓库存在 `migrations/0002-0004`，`0003` 正是 `ALTER TABLE users ADD COLUMN bookmarks`
- 正确表述：**迁移链不可从零重放**（缺 0001 基线、0003 在现 schema 撞 duplicate column、本地旧库从未跑迁移）
- 已按此回改我的报告，合并稿 3.3 的表述正确，无需改
